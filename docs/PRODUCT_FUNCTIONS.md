# SenseMu 产品功能地图

- 更新日期：2026-08-16
- 面向读者：产品、前端、后端、算法与测试同事
- 当前阶段：闭环 MVP 内部验证；尚未进入正式生产部署

本文说明用户看到什么、每个功能由谁使用、后端需要维护哪些业务事实。工程进度和后续优先级以 `docs/PROJECT_STATUS.md` 为准，架构取舍以 `docs/adr/` 为准。

## 1. 产品只保留四个一级页面

| 页面 | 主要用户 | 解决的问题 | 不放什么 |
|---|---|---|---|
| 工作台 | 算法生产方 | 管理数据、标注、训练、模型、发布和调用 | 商城购买、供应方结算、平台运维 |
| 算法市场 | 算法使用方 | 发现、比较、查看详情、订阅算法 API | 训练配置、服务运维、供应方后台 |
| 数据市场 | 数据使用方 | 发现、筛选、查看数据质量和授权条件 | 原始对象地址、内部清单、训练操作 |
| 我的 | 同一账号的生产与消费视角 | 查看商品、订单、收入、已购 API、用量、钱包和设置 | 重复的新建项目或发布入口 |

侧栏中的“数据与标注 / 训练 / 发布”是工作台内的真实对象集合，不是新的一级产品。收起侧栏后点击这三个图标，应先展开对应对象组，再由用户选择对象。

## 2. 用户与权限

一个用户可以属于多个工作区。所有业务对象必须归属于一个工作区，不能仅凭前端传入的项目或数据集 ID 授权。

| 角色 | 读取 | 日常生产操作 | 管理成员、发布、购买 |
|---|---|---|---|
| viewer | 可以 | 不可以 | 不可以 |
| member | 可以 | 上传、标注、训练等 | 不可以 |
| admin | 可以 | 可以 | 可以 |
| owner | 可以 | 可以 | 可以，并可管理管理员 |

生产环境使用 OIDC。`Authorization` 只确认用户身份，`X-Workspace-ID` 选择工作区；服务端每次请求都要复核有效成员关系和最低角色。开发模式会自动建立本地开发账号，仅供本机验证。

## 3. 工作台主链路

### 3.1 数据与标注

1. 创建项目和数据集。
2. 保存类别表，类别表是该数据集唯一的类别来源。
3. 上传图片，或上传视频文件并创建异步抽帧任务。
4. 创建标注任务：人工标注，或通过带清单的 YOLO / COCO 任务包交给成熟标注工具处理后导回。
5. 审核标注任务。目标检测只要求矩形框和类别，不要求自然语言描述。
6. 所有任务完成且数据检查通过后，冻结不可变数据版本。

关键约束：

- 视频源文件本身不可训练，只有抽出的图片进入素材、标注和冻结版本。
- 已产生标注或任务后不能随意修改类别表。
- 冻结版本固定素材、标注、划分、类别和质量快照，之后不能原地修改。
- 当前标注编辑器只覆盖首个目标检测闭环，不继续扩展为通用标注平台。
- 多模态智能预标注尚未接入，前端不能用示例框冒充真实结果。

### 3.2 训练与模型

1. 用户从项目训练页选择已冻结的数据版本和训练引擎。
2. API 创建幂等训练任务并写入不可变任务规格。
3. Worker 领取执行租约，启动隔离的 Ultralytics 训练容器并持续续租。
4. Worker 追加进度事件，上传模型、`results.csv`、混淆矩阵和类别指标等真实产物。
5. API 原子登记不可变模型版本。
6. 模型使用另一份未参与训练的冻结数据版本做独立验收。
7. 只有通过当前门禁的模型才允许发布。

关键约束：

- 训练数据检查和独立验收是两件事，不能用训练集指标替代验收结论。
- 页面指标只能来自真实产物；演示种子必须显式标记为演示或 Mock。
- 训练、验收和类别复核都有执行租约、超时、失联恢复与旧任务回写保护。
- 本地 ARM64 CPU 已跑通 Smoke Test，但当前指标和宽松门禁不代表生产质量。

### 3.3 发布与调用

项目内分为四个内部视图：

| 视图 | 当前作用 | 状态 |
|---|---|---|
| 实时分析 | 选择已发布视觉小模型并上传图片执行真实推理 | 已跑通本地闭环 |
| 批量处理 | 对冻结数据版本执行异步批量推理并下载 NDJSON 结果 | 已实现 |
| 服务设置 | 发布、启停、预热服务和轮换一次性密钥 | 已实现 |
| 事件 | 查看固定 PPE 事件及可靠 Webhook 投递状态 | 已实现 |

当前未开放：

- 多模态大模型：需要供应商服务端适配器、加密凭据、协议转换、超时重试、审计和计量。
- 实时视频流：需要加密流地址、网络白名单、采样 Worker、断流恢复、租约和事件去重。

在线图像推理、内部批量推理、市场调用计费和供应方凭据必须保持隔离，不能复用一套模糊接口。

## 4. 两个市场

### 4.1 算法市场

算法商品不能直接绑定一个随时变化的在线地址。供应方先从通过验收的生产服务固化不可变 `CapabilitySpec`，再创建商品并提交平台审核。只有审核通过的商品可被发现和订阅。

订阅流程：待支付订单 → 验签收款 → 激活授权与额度 → 管理员一次性领取密钥 → 网关预留额度 → 推理成功后确认用量和供应方收入。失败请求释放预留；全额退款立即撤销授权。

正式支付、KYC/KYB、钱包和结算渠道尚未选定，页面必须保留“未开通”事实，不能伪造余额或支付成功。

### 4.2 数据市场

数据卡只能来自自有冻结版本，并包含来源、采集方式、覆盖范围、已知限制、隐私处理、许可证和质量快照。公开页面不返回对象存储地址或内部 manifest。

当前已固化“授权后复制到买方工作区”的交付规范，但购买、下载和实际交付仍未开放。

## 5. 我的

“我的”在同一页切换两个视角：

- 创作与销售：供应方资料、已上架算法和数据、销售订单、收入事实、跨项目训练与在线服务汇总。管理员和所有者可以从这里提交算法商品审核，或从冻结数据版本创建数据卡；这两个动作不会复制工作台的训练和发布流程。
- 购买与使用：已购 API、数据订单、成功用量、支付状态和钱包状态。

项目训练和服务创建仍只在工作台发生；“我的”只负责跨项目汇总和商业事实，不重复放新建入口。

上架动作保持两条不可混淆的事实链：

1. 算法商品必须引用已发布生产服务上的不可变 `CapabilitySpec`。提交后状态为待审核，审核通过前不进入算法市场。
2. 数据卡必须引用当前工作区尚未公开的冻结数据版本。创建时必须填写来源、采集方式、覆盖范围、限制、许可、隐私处理和权利确认；数据卡可以公开发现，但购买、授权和交付仍由商业合同能力控制。

普通成员仍可使用工作台生产数据和模型，但不能读取供应方账本或创建商品；页面会给出继续生产入口，而不是展示一个会失败的供应方表单。

## 6. 运行边界

| 进程 | 默认端口 | 职责 | 不承担的职责 |
|---|---:|---|---|
| Web | 3000 | 页面、交互、调用核心 API/推理网关 | 不保存业务事实，不持有内部服务凭据 |
| Core API | 8000 | 身份、工作区、数据、训练编排、发布、市场和账本事实 | 不直接执行 GPU 训练或模型推理 |
| Worker | 无公网端口 | 训练、验收、抽帧、维护和 Webhook 异步任务 | 不向浏览器提供接口 |
| Inference Gateway | 8080 | 公网推理鉴权、路由、额度预留、计量、稳定协议 | 不保存模型，不直接访问任意 URL |
| Inference Runtime | 8090 | 受限模型缓存和真实预测 | 仅供网关/Worker 调用，不对终端用户开放 |

生产事实源为 PostgreSQL；Redis 只承载队列与短期状态；S3 兼容存储承载数据、模型和报告。当前本地预览使用 SQLite 与本地对象目录。

## 7. 后端开发时必须保持的边界

- 所有租户数据查询都带工作区边界，并由服务端验证成员关系。
- 创建训练、验收、批处理和支付意图时使用幂等键或请求号。
- 异步任务只接受当前执行租约的回写，过期 Worker 不能覆盖新尝试。
- 数据版本、模型版本、能力契约、工作流和交付规范都是不可变版本，不原地覆盖。
- 密钥只展示一次，数据库只保存摘要；内部凭据与客户 API 密钥分开。
- 任何价格、指标、标注数量和服务状态都来自真实后端事实，不由前端估算。
- 暂未接入的功能明确返回不可用或保持按钮关闭，不生成 Mock 成功结果。
