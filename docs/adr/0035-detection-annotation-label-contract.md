# ADR-0035：目标检测标注的类别与备注契约

- 状态：已采纳
- 日期：2026-08-14

## 背景

SenseMu 当前首个训练切口是目标检测。数据页提供轻量的任务预览和外部标注工具交接，但不能把一个预览编辑器误解为通用标注平台。需要明确“画完框以后什么是训练必需信息”，避免在每个框上堆叠描述字段。

## 决策

- 每个矩形框必须有一个来自数据集类别表的整数类别编号；类别名称只从数据集的已保存类别表读取，不允许在标注页临时创建或改名。
- 目标检测的训练标注不要求自然语言描述、标题或自由文本。YOLO 标签文件只保存 `class_id x_center y_center width height` 五个字段，坐标使用 0 到 1 的归一化格式。
- 业务备注是可选的上下文信息，不进入首期训练标签契约。若后续需要记录审核意见、遮挡原因或异常说明，应作为任务审核记录或素材级备注单独建模，不写入 YOLO 标签文件。
- 智能预标注结果必须携带模型版本、置信度和人工接受记录后才能进入训练数据；在供应商、成本、隐私和审核合同确定前，前端入口保持未开放。
- 多边形、分割掩码、关键点和视频流标注不复用目标检测的五字段契约；接入时创建独立格式版本和校验器。

## 交互规则

- 创建标注任务前先在数据页保存类别表；已有标注或任务后类别表不可修改。
- 标注页选择类别后画框，保存只回写 YOLO 标签；提交检查只检查素材完整性、坐标合法性和类别编号，不要求补写描述。
- 需要更丰富协作能力时，从“导出任务包”交给已验证的外部标注工具；导入必须保留 `sensemu-task.json` 并通过任务、数据集、素材哈希和标签全量校验。

## 非目标

- 首期不实现每个框的描述输入、自然语言问答或自由标签。
- 不在浏览器预览编辑器中扩展协同锁、复杂几何编辑或多模态模型编排。
