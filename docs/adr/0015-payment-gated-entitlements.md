# ADR-0015：收款验证先于市场调用授权

- 状态：Accepted
- 日期：2026-08-10
- 取代：ADR-0009 中“支付不作为授权前置”和“全额退款不撤权”的临时决策

## 决策

付费算法商品的订单创建不等于调用授权。买方下单时平台只创建待支付订单、渠道无关的支付意图和待收款记录；不起算有效期，不发放额度，不生成密钥。

只有支付适配器完成渠道验签，且核心 API 对金额、币种、支付意图和事件幂等性校验通过后，才在同一事务内激活 30 天额度。支付成功事件不向支付适配器返回调用密钥。

## 密钥发放

授权激活后，买方工作区的管理员必须通过用户身份与工作区权限门禁主动领取密钥。领取只成功一次，数据库仅保存前缀、SHA-256 摘要和领取时间。支付回调、日志和普通查询响应都不得包含明文密钥。

已激活但未领取的授权不能轮换密钥。领取后可以主动轮换，旧密钥立即失效。

## 免费与退款

订单应付金额为零时，支付意图标记为“无需支付”，订单标记为“免付费”并直接激活授权；密钥仍需买方管理员一次性领取。免费订单不接受支付回调。

部分退款保留当前授权。当累计退款达到已收款全额时，平台立即将当前授权标记为已退款，清除密钥前缀和摘要，后续推理调用必须失败。历史用量、收入计提和支付事件保留为审计事实，不做物理删除。

## 重新下单与旧事件

待支付或支付失败的当期订单重复操作时返回原支付意图。已退款、已过期或额度用尽后重新购买会生成新订单。只有最新订单的收款可以激活当前授权；过时订单的延迟收款仅记录为商业事实，不覆盖新授权。

## 当前非目标

本次不选定 Stripe、微信支付、支付宝或其他渠道，不创建虚假收银台，不实现优惠、税务、发票、自动续费、抽成、结算或提现。首个渠道适配器必须在目标市场与签约主体确定后单独实现。
