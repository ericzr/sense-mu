# ADR-0028：冻结数据版本的批量推理产物

## 背景

在线推理适合低延迟集成，不能承担批量检查、离线交付或对历史数据复跑的职责。竞品均将批量处理、版本化数据和可下载结果视为视觉 AI 平台的基础能力；但将它们直接塞进公网推理接口，会模糊权限、计量和失败恢复边界。

## 决策

首期将批量推理建模为 `Run(run_type=inference.batch)`，与训练和独立验收共用领取、心跳、取消、失联恢复与事件审计机制。创建任务时固化：

- 已发布的项目内目标检测服务及模型产物；
- 已冻结的数据版本、所选数据划分和资产数量；
- 置信度、IoU、最大检测数和推理尺寸；
- 产物目录与任务规格内容。

Worker 只读取冻结 manifest 中的平台对象地址，每次最多向受限推理运行时提交 4 张图片。它输出以 `asset_id` 关联预测的 NDJSON 和报告；结果中不保留原始对象地址。控制面仅在 Worker 持有当前执行租约、任务正在运行且产物目录属于该任务时登记 `BatchInferenceResult`。

批量任务不经公网网关，也不产生市场授权、额度预留或成功调用计量。市场买方的离线批处理属于未来独立的商品交付与计费决策，不能借用供应方工作区的内部任务权限。

## 后果

- 批处理可复现、可取消，并且可在 Worker 失联时按统一规则恢复。
- 模型、数据和参数的追溯与训练链路一致，结果可供客户下载和后续审计。
- 首期只支持图片目标检测、平台对象存储与 NDJSON，不支持任意 URL、视频、自由处理图或通用导出格式。
