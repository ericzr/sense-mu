# ADR-0006：受限的 Ultralytics 推理运行时

- 状态：Accepted
- 日期：2026-08-09

## 决策

真实模型推理由独立的 `apps/inference-runtime` 进程执行，不嵌入公网推理网关。网关完成端点解析和密钥校验后，以内部凭据向运行时发送已经授权的模型版本、对象地址、任务类型和受限参数；运行时不访问业务数据库，也不接受用户选择任意模型文件。

首个运行时只支持 `object-detection` 与 `detections.v1`，使用 Ultralytics YOLO 加载训练产物。对外返回统一结构：图片尺寸、类别编号、类别名称、置信度和 `xyxy` 边界框。训练框架的原始对象不会直接透传给客户。

## 输入和参数边界

推理输入只允许两类来源：当前平台对象存储中的 `local://` / 指定 S3 存储桶地址，或 JPEG、PNG、WebP 的 Base64 Data URL。运行时不抓取任意 HTTP URL，避免形成服务端请求伪造入口。公网请求每批最多 4 张图片，页面单张上传限制为 8 MB；Base64 原文不会出现在响应中。

可调参数固定为置信度、IoU、最大检测数和图像尺寸。未知参数由请求模型直接拒绝，不能透传任意 Ultralytics 命令或文件路径。

## 模型缓存与并发

运行时将模型产物物化到独立缓存目录，按模型版本维护小型 LRU 缓存，默认最多保留 2 个模型。首次调用加载权重，后续调用复用内存模型；发布端可以通过网关显式预热模型，预热沿用端点鉴权但不产生计量记录。

实例使用有界信号量保护加载与推理的总并发，默认 CPU 实例同时只接收 1 个任务。请求最多在实例内等待 2 秒，容量仍不可用时返回带 `Retry-After` 的 `429`，避免无界排队耗尽内存。同一模型继续使用独立推理锁，防止 Ultralytics/PyTorch 对象出现非线程安全状态。提高实例并发必须结合设备显存或内存实测，不由用户参数动态决定。

容器以非 root 用户运行，根文件系统只读，只开放临时目录和模型缓存卷。当前默认 CPU；GPU 部署只需替换设备配置与容器资源声明，不改变网关协议。

## 超时与健康状态

网关分别设置控制面解析、运行时执行、成功计量和健康探测超时，并返回可区分的错误码。运行时超时或失败不会写入成功用量；推理已完成但计量未确认时会明确失败，调用方可沿用请求编号重试，由核心 API 幂等登记用量。

运行时就绪接口返回缓存数量、活动请求、等待请求和可用容量。网关就绪接口同时探测核心 API 与运行时并聚合上述状态；实例容量暂时占满不会使进程失去就绪资格，但 `accepting_requests` 会显示为否，实际请求由容量保护返回 `429`。

## 安全边界

PyTorch 权重加载本质上可能执行序列化内容，因此当前运行时只允许加载 SenseMu 训练链路产生、通过门禁并由核心 API 发布的产物。未来算法市场接收第三方权重前，必须增加隔离转换、恶意模型扫描或安全格式，不得直接复用此信任边界。

## 当前限制

模型缓存和容量计数是单实例本地状态，不跨运行时副本共享；进程重启后仍需重新加载内存模型。当前只有快速失败和明确超时，没有跨实例排队、熔断器、自动扩缩容或按模型资源规格调度，首版不提前建设集群调度器。
