# ADR-0011：工作区邀请与权限审计

- 状态：Accepted
- 日期：2026-08-09

## 决策

工作区协作只建设三个必要能力：成员邀请、角色调整和权限审计。邀请由管理员或所有者创建，接受邀请必须使用与目标邮箱一致、且由身份提供方明确标记为已验证的登录身份。邮箱只用于确认邀请接收者，不替代“签发方 + subject”这一身份主键。

邀请凭据使用高熵随机值，数据库只保存 SHA-256 摘要和用于辨认的短前缀。完整邀请链接仅在创建响应中返回一次；链接把凭据放在浏览器地址片段中，避免凭据随普通页面请求进入访问日志。平台当前不伪造邮件投递状态，由管理员自行通过可信渠道发送链接。

## 权限边界

- 管理员可以邀请成员或查看者，并调整、停用普通成员。
- 只有所有者可以邀请或授予管理员角色，也只有所有者可以调整、停用管理员。
- 所有者身份不能通过普通成员管理接口变更；当前操作者也不能在该接口中停用或降级自己。
- 已停用成员立即失去工作区访问权，历史成员记录不会删除。
- 本阶段不实现所有权转移和成员恢复，避免在缺少二次确认与恢复流程时制造不可逆状态。

## 审计

邀请创建、接受、撤销以及成员角色调整、停用都会追加 `WorkspaceAccessEvent`。事件只追加，不提供更新或删除接口，并记录操作者、目标、邀请和必要的非敏感上下文；邀请明文凭据绝不进入审计详情。

## 非目标

本次不建设邀请邮件发送、域名自动加入、批量成员导入、SCIM、所有权转移或细粒度自定义角色。这些能力只有在明确的企业客户需求和身份提供方方案确定后再扩展。
