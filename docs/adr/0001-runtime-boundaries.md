# ADR-0001: 首版运行时边界

- 状态：Accepted
- 日期：2026-08-07

## 决策

首版使用一个 Web 应用、一个 FastAPI 模块化单体、一个 Celery Worker 进程和一个独立推理网关。业务模块依赖按单向边界组织，但共享 PostgreSQL，不通过网络拆成微服务。

## 原因

- 产品仍在验证核心主链路，跨服务一致性与运维成本暂时没有回报。
- 训练、导入与推理的运行时特性明显不同，需要进程隔离。
- 推理网关将承载计量、限流与商业化，安全和性能边界值得单独保留。

## 升级条件

仅当某模块在扩缩容、安全、发布频率或团队责任上出现可量化的独立边界时，才将其拆为网络服务。
