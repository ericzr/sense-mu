# ADR-0030：训练算力与算法托管跟随项目生命周期

- 状态：已采纳
- 日期：2026-08-11

## 背景

供应方需要两类平台服务：训练时临时使用的计算资源，以及模型发布后持续或按需运行的推理资源。两者生命周期、状态和计费依据不同。如果统一包装成“算法服务器”并增加一级页面，用户必须先理解基础设施，且会破坏已经收敛的四页面结构。

成熟产品通常从数据版本或模型上下文创建训练和部署，再提供跨项目的全局管理。SenseMu 已有 `DatasetVersion → Run → ModelVersion` 与 `ModelVersion → Deployment → UsageRecord` 两条真实链路，应直接沿用这些事实。

## 决策

### 训练服务

- 创建入口固定在 `工作台 → 项目 → 训练`。
- 当前唯一可用方式称为“平台训练”，不向用户展示 Docker、Worker 或节点信息。
- 任务详情继续展示真实状态、进度、配置、事件和产物。
- 在资源分配与计费合同落地前，只显示“费用功能尚未开通”，不提供虚构算力档位或估价。

### 算法托管

- 创建入口固定在 `项目 → 发布与调用`，用户动作称为“发布在线服务”。
- 在线服务必须绑定通过当前独立检查的模型版本。
- 服务详情承担启停、API 地址、密钥、健康度、调用量和测试；市场商品继续绑定不可变能力契约，不直接绑定任意模型文件。
- 当前真实运行时按“共享在线服务”理解。专属实例、自有服务器和边缘设备只有在具备真实调度、健康检查与计量后才开放选择。

### 跨项目管理

- `我的 → 创作与销售` 增加一个“算力与托管”区块。
- 区块内只切换“训练任务”和“在线服务”，分别汇总当前工作区的真实记录。
- 每条记录跳回所属项目详情；汇总区不复制训练或发布表单。
- 训练费用、托管费用和算法销售收入使用不同账目，不能用一个模糊余额相互抵消。

### 市场边界

- 算法市场只面向购买方，不出现供应方服务器控制。
- 购买方只看到交付方式、服务状态、质量证据、输入输出、响应指标、限制和价格。
- 服务器型号、执行器、节点地址与容器状态属于平台内部事实。

## 首期边界

首期只建设：

- 平台训练任务及跨项目汇总；
- 共享在线服务及跨项目汇总；
- 已有调用计量；
- 费用未开放的真实状态。

暂不建设：

- GPU 自由选型和算力市场；
- 专属实例的自动扩缩容；
- 自带云账号或自有 GPU 接入；
- 边缘设备与摄像头设备管理；
- 人工代训练、专家调参和承诺效果的服务订单。

## 后续合同

正式计费前至少需要新增以下可审计事实：

- 训练任务资源规格、分配时间、释放时间和计费用量；
- 在线服务托管方式、实例规格、运行区间和计费用量；
- 每条费用记录关联工作区、项目、任务或服务、费率版本和幂等来源；
- 销售收入、平台服务费、训练费用、托管费用与退款分别记账。

## 结果

普通用户继续只需要理解“训练”和“发布在线服务”。平台可以逐步增加远程 GPU、专属托管和自有设备能力，而无需改变一级页面或破坏现有项目闭环。
