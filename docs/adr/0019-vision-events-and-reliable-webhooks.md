# ADR-0019：视觉事件使用持久化记录和可重试 Webhook 投递

- 状态：Accepted
- 日期：2026-08-10

## 决策

首期将视觉业务事件写入 `VisionEvent` 事实记录，再为每条事件创建唯一的
`WebhookDelivery`。推理网关通过受保护的内部契约提交事件；相同工作流与幂等键
只会形成一条事件和一条投递记录。

Worker 领取投递后，使用稳定 JSON 序列化生成请求体，并以
`HMAC-SHA256` 计算 `X-SenseMu-Webhook-Signature`。任意 2xx 响应视为成功；
网络错误和非 2xx 响应按指数退避重试，最多八次。Worker 定时回收待投递、到期重试
和超时占用的记录。项目成员可在在线服务页查看近期事件、投递状态、次数和错误摘要。

## 原因

客户业务系统需要的是可追溯的告警事实，而不是一次尽力而为的 HTTP 调用。将事件
和投递拆开，可以在不引入 Kafka、独立事件总线或通用工作流引擎的情况下保证失败
可见、重复可控、投递可恢复。

## 安全与边界

- Webhook 目标沿用工作流创建时的公开 HTTPS、无凭据、默认端口约束。
- 签名密钥仅位于控制面配置，Worker 只接收已经签名的投递负载。
- 不记录原始图片或推理输入；事件负载由网关按业务事件契约构造。
- 不支持自定义代码、任意回调链、Kafka/MQTT、人工节点或自由拖拽画布。

## 后续

首个固定 PPE 事件解释器已由推理网关调用该内部契约：仅在用量计量成功后，对
`ppe-violation-webhook.v1` 生成帧级安全帽和反光衣缺失风险事件，并按来源与时间窗口
去重。新业务事件或新的流程模板，必须先定义稳定的输入、去重键和可验证的验收标准，
再扩展运行时。
