# ADR-0029：面向用户的四页面信息架构

- 状态：Accepted
- 日期：2026-08-11

## 问题

现有产品将生产、购买、供应方管理和平台内部事实铺在多个一级页面。算法市场同时展示商品目录、商品提交、API 订阅、用量、买方订单和卖方收入；数据市场同时展示数据发现和数据发布；另有供应方中心、在线服务和设置等独立入口。

这使用户难以判断“这个页面是用来买、卖，还是生产算法”，页面标题、边距和解释文案也因为各自实现而产生跳动。

## 决策

用户视角只保留四个一级页面：

1. `工作台`：生产端入口，用于创建和继续完成算法项目。
2. `算法市场`：消费端商城，用于发现、筛选、预览和购买算法 API。
3. `数据市场`：消费端商城，用于发现、筛选、预览和购买数据集。
4. `我的`：用户资产与账务中心，在同一页中切换“生产端”和“消费端”视图。

“生产端 / 消费端”是用户的工作视图，不替代工作区成员的服务端权限校验。同一账号可以同时是算法生产者和购买者。

## 四个页面的责任

### 工作台

首屏只保留：

- 数据集、训练中任务、可用模型和本月调用等关键数据；
- 项目列表，项目可打开继续迭代，并在有真实后端状态后支持暂停与继续；
- 一个“新建项目”入口，进入项目创建与训练准备流程；
- “我的数据集”列表，可进入对应项目数据页。

项目内部继续使用 `概览 / 数据 / 训练 / 发布与调用` 四个步骤。这些是项目二级页面，不进入主导航。

工作台不再单独展示算法市场宣传卡、“快速开始”的重复入口或多个新建训练按钮。

项目状态收口为 `进行中 / 已暂停 / 已归档`。“暂停”表示暂时禁止新的训练、验收、批量推理和发布操作，不强制终止已经在运行的任务；“继续”恢复新操作。归档是二级操作，不与暂停混用。目前后端只有归档字段，暂停与继续需要作为本次收口的新状态合同实现。

### 算法市场

只展示消费者在购买前需要的内容：

- 搜索、任务类型、使用场景、交付方式和价格筛选；
- 商品卡片：名称、能解决什么问题、适用场景、价格、发布者和验收状态；
- 商品详情：输入、输出示例、限制、计费方式和购买动作。

不再展示商品提交、审核状态、我的 API、用量、买方订单、卖方收入或支付内部状态。这些全部进入“我的”。

### 数据市场

与算法市场使用同一商城结构：

- 搜索、任务类型、场景、许可、数量和价格筛选；
- 商品卡片：名称、样本数、类别数、场景、价格、发布者和可用范围；
- 商品详情：预览样本、类别分布、质量、来源、许可和交付方式。

数卡发布、许可声明编辑和销售记录进入“我的 > 生产端”。

### 我的

页面顶部使用明确的分段开关：`生产端 | 消费端`。

生产端展示：

- 可用余额、待结算收入和收入明细；
- 我上架的算法、我上架的数据，以及提交和审核状态；
- 销售订单、退款和客户调用数据；
- 训练与推理算力服务器的用量、费用和运行状态；
- 发布者资料、身份、收款与结算设置。

消费端展示：

- 钱包余额、本月消费和消费明细；
- 已购或订阅的算法 API，包括密钥、额度、到期时间和调用地址；
- 已购数据、交付状态和许可；
- 购买订单、退款和 API 消费用量。

成员、安全和工作区设置作为“我的”中的二级设置，不再占用一级导航。尚未接入真实钱包、收款或结算服务时，界面必须显示“尚未开通”，不使用虚假数字。

## 现有页面迁移

| 现有内容 | 新位置 |
|---|---|
| `/providers` 供应方中心 | `/me?view=producer` |
| 算法市场的提交商品与审核 | `/me?view=producer&tab=algorithms` |
| 算法市场的 API 订阅、用量和买方订单 | `/me?view=consumer` |
| 算法市场的卖方收入 | `/me?view=producer&tab=orders` |
| 数据市场的发布数据卡 | `/me?view=producer&tab=data` |
| `/settings` | `/me?tab=settings` |
| `/services` | 项目内“发布与调用”二级页面 |

旧路由在迁移期内保留跳转，不再出现在主导航。

## 布局与文案规则

- 四个一级页面共用同一内容宽度、水平边距、顶部间距和标题基线，切换页面时标题不跳动。
- 页头只保留一个主标题和必要操作；不在主标题上方重复“工作台”、“调用授权市场”、“可信数据目录”等英眉文字。
- 卡片标题不使用“分组名 + 标题”的双重命名；例如“工作区项目 / 项目列表”简化为“项目”。
- 用户主流程使用“项目、数据集、训练、模型、API、订单、余额、用量”等日常词语。
- `CapabilitySpec`、“能力契约”、“调用授权”、“支付意图”、“收入计提”、“不可变清单”和“质量门禁”等内部术语仅保留在高级详情、审计或技术文档中。
- 有操作影响、风险、限制或下一步时才显示解释文字；不用口号式文案填满空间。

## 实施顺序

1. 先统一主导航、页头容器、标题基线和术语。
2. 再收口工作台的入口与内容。
3. 将两个市场改为纯商城，保持现有后端事实不变。
4. 建立“我的”，迁移生产端和消费端的资产、订单、用量和设置。
5. 最后移除重复入口、为旧路由建立兼容跳转，并完成桌面端和移动端回归。

## 非目标

本次不删除后端的审核、支付、额度、计量、数据来源或权限事实。它们继续保证系统真实性，但不再默认暴露给普通用户。
