# ADR-0010：用户身份与工作区授权

- 状态：Accepted
- 日期：2026-08-09

## 决策

核心 API 将身份认证与工作区授权分开。OIDC 凭据只证明“当前用户是谁”，`WorkspaceMembership` 才决定该用户能否访问某个工作区以及可以执行哪些操作。前端传入的 `X-Workspace-ID` 只是工作区选择器，不再被视为可信租户上下文。

`UserAccount` 以“签发方 + subject”唯一映射外部身份。邮箱和显示名只用于展示，可以随后续凭据同步，不用作授权主键。被停用的用户即使持有有效 OIDC 凭据也不能访问业务数据。

## 身份验证模式

平台只保留两种明确模式：

- `development`：使用配置中的本地开发者身份，并自动为其补齐本地已有工作区的所有者关系。该模式仅允许在 `development` 或测试环境使用，非开发环境会返回服务配置错误，不会静默降级。
- `oidc`：要求 Bearer JWT，通过配置的 JWKS 验证 RS256 签名，并精确校验签发方、受众、过期时间和 subject。缺失配置时失败关闭，不接受未验签声明或由客户端直接传入的用户标识。

当前不在平台内自建密码系统、会话存储、找回密码或多因素认证。这些能力由后续选定的身份提供方负责。

## 成员角色

工作区成员使用四级角色：

- 查看者：只能读取工作区数据。
- 成员：可以执行数据、标注、训练和评测等日常写操作。
- 管理员：在成员能力之上，可以发布或停用在线服务、轮换密钥、上架算法商品和购买市场授权。
- 所有者：拥有管理员的全部能力，并作为后续成员管理、计费主体与所有权转移的责任角色。

没有活跃成员关系时统一拒绝访问。已暂停的成员关系不会被视为任何角色。

## 历史数据迁移

身份模型上线前已存在的工作区会关联到一个不可登录的历史托管账号，以避免在不知道真实业务所有者的情况下伪造外部用户身份。本地开发模式会额外为开发者建立所有者关系；生产迁移时必须通过受控的管理流程将所有权转移给真实主体。

## 非目标

本次不选定最终身份提供方，不建设公网登录页、邀请邮件、SCIM 同步、单点登出或成员所有权转移界面。推理网关、Worker 和支付适配器的内部服务凭据继续与用户 OIDC 凭据分离。
