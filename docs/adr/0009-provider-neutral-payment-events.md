# ADR-0009：渠道无关的支付事件边界

- 状态：Superseded in part by ADR-0015
- 日期：2026-08-09

## 决策

在确定具体支付渠道之前，核心平台只建立渠道无关的支付状态边界，不生成支付链接、不模拟扣款成功，也不把人工按钮作为收款事实。

每笔 `MarketplaceOrder` 在创建时同事务生成一个 `MarketplacePaymentIntent`，只固化平台支付意图编号、应付金额和币种。初始状态为“支付渠道待接入”，渠道名称和渠道支付编号为空。

## 适配器契约

具体支付适配器负责接收渠道原始回调、保留验签所需原始字节、验证渠道签名，然后通过受独立服务凭据保护的内部接口提交归一化事件。核心平台不直接信任公网请求中声称的“支付成功”。

归一化事件必须包含渠道名称、渠道事件编号、渠道支付编号、平台支付意图编号、事件类型、金额、币种、发生时间和原始载荷的 SHA-256 摘要。核心平台不保存未筛选的原始回调，避免将支付用户隐私和无关渠道字段扩散到业务库。

## 幂等与金额校验

`MarketplacePaymentEvent` 对“渠道名称 + 渠道事件编号”强制唯一。同一事件以相同载荷摘要重试时返回已有结果；事件编号相同但金额、类型、支付意图或摘要不同时直接拒绝。

收款成功或失败事件的金额和币种必须与支付意图完全一致。金额继续以人民币百万分之一元的整数存储。已收款后到达的过时失败事件只追加记录，不能将订单回退为未收款。

## 退款边界

当前只接受渠道确认成功的退款事件。`MarketplaceRefund` 以渠道退款编号唯一追加存储，部分退款可以累积，但累计退款不能超过已收款金额。本 ADR 原先暂不将退款与撤权联动；ADR-0015 已确定部分退款保留授权、全额退款立即撤权的最新时序。

## 当前非目标

当前不选择 Stripe、微信支付、支付宝或其他渠道，不创建收银台，不实现优惠、税务、发票、自动续费、抽成、结算或提现。本 ADR 原先暂不以支付作为调用授权前置；ADR-0015 已将收款验证确立为付费商品的授权前置。
