# ADR-0020：算法商品必须引用不可变能力版本

- 状态：Accepted
- 日期：2026-08-10

## 决策

算法市场不再直接把在线服务当作商品。每个新建商品必须显式引用一个已发布的
`CapabilitySpec`；服务端从契约解析其生产服务、模型、输出协议、适用场景和限制，
不接受客户端提交的替代引用。

平台审核批准时会再次验证能力契约和关联生产服务仍处于可用状态。公开目录、购买
和市场推理授权只接受已绑定能力契约的商品。市场页展示能力名称、版本、输出协议、
已验证场景和不适用条件，供买方在购买前判断适用性。

## 迁移策略

迁移会把已有商品按其生产服务回填到相同服务的能力契约。无法找到能力契约的历史
商品会标记为 `legacy_unbound` 并退出公开目录；供应方需要先固化能力契约，再重新
提交审核。不会用当前服务状态或一段商品文案伪造历史能力版本。

## 原因

商品价格和调用额度只能描述交易，不足以说明客户实际购买了什么。用不可变能力版本
连接商品、独立验收、服务端点和模型版本，才使市场展示、审核意见、购买决策和后续
追溯指向同一份事实。

## 当前非目标

本次不支持一个商品组合多个能力版本、自动将能力更新迁移到已售商品、买方自定义
输入输出协议，或开放跨供应方能力组合。能力更新仍需要新的生产服务和新的
`CapabilitySpec`。
