# ADR-0004：版本化评测门禁与不可变报告

- 状态：Accepted
- 日期：2026-08-09

## 决策

评测门禁是项目级、版本化的业务规则。创建新规则时生成新的 `EvaluationPolicy`，旧版本只退出当前生效状态，不覆盖名称、指标或阈值。项目同一时间只有一个生效策略；创建过程锁定项目记录并由 `(project_id, version_number)` 唯一约束兜底，避免并发生成重复版本号。

训练完成并登记 `ModelVersion` 后，如果项目存在生效策略，API 会立即使用模型产物回传的验证指标执行门禁。每次“模型版本 + 策略版本”至多产生一份 `Evaluation`，重复回调或重试直接复用已有结果。规则支持数值指标的 `>=`、`<=`、`>`、`<` 比较；指标缺失或不是有限数字时明确判定失败，不使用默认值补齐。

评测结果同时写入数据库与对象存储中的不可变 `report.json`。报告固化模型版本、数据集版本、策略完整规则、原始指标、逐条结果、结论和评测时间。模型状态由结果更新为 `approved` 或 `rejected`，训练任务本身仍保持 `succeeded`，因为训练成功与质量是否达标是两个不同事实。

## 指标来源边界

当前评测来源固定记录为 `training-validation`：它只使用 Ultralytics 训练产物中的验证指标，不能被描述为独立验收评测。Studio 必须明确展示这一来源，在没有持久化报告时不得生成或伪造质量建议。

后续引入独立验收集时，应增加新的评测执行任务和来源类型，读取单独冻结的数据集版本并运行真实推理；不得把当前验证指标原地改名为验收结果。

## 后果

- 已有模型可以在创建新策略版本后人工重评，历史报告保持可追溯。
- 策略更新不会静默改变旧报告结论。
- 发布控制面后续只能接受通过指定门禁版本的模型；不能仅凭训练成功直接发布。
