# ADR-0033：视频文件抽帧必须产出真实数据集素材

- 状态：已采纳
- 日期：2026-08-14

## 背景

数据页此前可以选择视频或填写视频流地址，但提交后只在浏览器中显示预计图片数与“处理中”。没有上传来源视频、持久任务、Worker 产物或数据集写回，因而也不能进入真实标注流程。

## 决策

- 本轮只开放本地 MP4、MOV 和 WebM 文件；视频流在加密凭据、地址保密、网络访问和任务恢复合同明确前保持不可用。
- 原始视频登记为数据集的 `source_video`，用于追溯，不计入图片素材数、不进入标注任务，也不进入冻结训练版本。
- 抽帧使用独立 `VideoExtractionJob`，保存来源、间隔、去重选项、状态、进度、执行尝试和错误。
- API 通过 Celery 的 `extraction` 队列分发；Worker 使用 `ffprobe` 读取元数据、用 `ffmpeg` 生成 JPEG，并把带 SHA-256、尺寸和受控地址的产物回报给 API。
- API 只接受当前任务产物目录内且可验证的图片，按校验和去重后登记为 `training_asset`。成功后前端刷新数据集，用户可以创建真实手动标注任务。
- 抽帧执行与训练任务一样使用租约心跳和执行尝试令牌。Worker 失联后，维护任务会在租约超时后回收：未达到最大尝试次数的任务重新排队，取消中的任务转为已取消，超过上限的任务明确失败；旧 Worker 的心跳、事件和结果不会被接受。
- 数据页在抽帧任务处理中提供取消操作。取消请求会阻止任务完成时登记新的训练素材，已上传到内部产物目录但未登记的文件不会进入数据集。
- 每次成功抽帧会按帧序号持久化其实际登记的素材清单，包括复用的去重素材。完成态任务可幂等创建一个来源明确的手动标注任务；任务只包含该次抽帧产物，不会按文件名或时间猜测，也不会混入数据集中的其他素材。
- 视频输入、抽帧、训练、批量推理和公开 API 推理保持不同任务边界。

## 运行前提

- Worker 宿主机必须提供 `ffmpeg` 与 `ffprobe`。
- Worker 必须消费 `extraction` 队列，并能访问 API、对象存储和 Celery Broker。
- 单个任务最多登记 20,000 张图片，抽帧间隔限制为 0.1 至 60 秒。

## 非目标

- 不接收或明文保存 RTSP 等视频流地址。
- 不实现目标跟踪、模糊帧质量模型或智能预标注。
- 不把来源视频当作可直接训练或标注的图片。
