# ADR-0007：算法市场调用授权与额度预留

- 状态：Superseded in part by ADR-0015
- 日期：2026-08-09

## 决策

算法市场首版只销售已经通过质量门禁、发布到生产环境且当前推理运行时支持的目标检测服务。`MarketplaceListing` 固化供应方工作区、在线服务、商品说明、每千张图像价格和 30 天额度；商品不复制模型文件，也不允许绕过原有发布门禁。

买方工作区通过 `MarketplaceSubscription` 持有订单和授权状态。价格与额度在下单时生成快照，后续商品改价不会追溯修改既有订单。ADR-0015 已将 30 天有效期和额度的起算点改为验签收款成功；市场密钥与供应方在线服务密钥完全分离，由买方管理员在授权激活后一次性领取，数据库只保存前缀和 SHA-256 摘要。

当前版本记录价格、订单、验签收款、授权、额度和成功用量事实，但不声称已经接入具体收银台、开票或供应方分账。

## 调用授权与原子额度

公网网关在执行推理前，将请求编号和图片数交给核心 API 授权。供应方自己的服务密钥不受市场额度限制；市场密钥必须属于该商品的有效授权。

对市场调用，核心 API 在锁定授权记录后创建 `UsageReservation` 并增加预留额度。运行时成功后，计量记录、预留转为已消费以及授权已用额度在同一数据库事务提交；运行时明确失败或超时时，网关释放预留。相同请求编号重复授权或计量不会重复扣额，预留内容不一致时直接拒绝。

这套流程避免“先检查、后扣减”在并发场景突破额度。PostgreSQL 使用行级锁保证同一授权的额度串行更新；本地 SQLite 用于功能开发，不作为高并发计费数据库。

## 失败边界

额度不足返回 `402`，授权到期返回 `403`，密钥错误返回 `401`。运行时成功但计量响应丢失时，网关不会主动释放额度，因为核心 API 可能已经提交；调用方应沿用请求编号重试，由幂等记录收敛状态。

运行时失败后的释放首先由网关同步尽力执行。Worker 每分钟额外扫描超过 180 秒仍处于待确认状态的预留，锁定授权后释放额度；该超时高于当前运行时和计量超时总和，不会回收仍在正常响应窗口内的请求。生产化时仍需为连续回收失败和异常规模增加告警。

买方工作区可以查询只包含成功计量的用量明细，记录请求编号、算法商品、供应方、图像数、发生时间和按授权价格计算的参考费用。预留、释放和失败请求不进入参考费用，参考费用也不能被解释为已扣款。

## 暂不建设

首版不加入购物车、优惠券、自动续费、具体外部支付渠道、税务、发票、多层分销、动态竞价或复杂分成。商品下架、结算账期和供应方余额仍需单独设计，不能由调用额度反推“已支付”。
