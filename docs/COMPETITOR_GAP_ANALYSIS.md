## 仍需推进

1. 数据交换：对象存储、COCO/YOLO 导入导出与成熟标注工具适配。
2. 训练报告：真实曲线、混淆矩阵、类别级指标和模型对比。
3. 生产运维：正式 PostgreSQL/对象存储、备份恢复、部署平台告警与首发地区支付身份适配。
4. 在真实客户吞吐、格式和保留策略明确后，再扩展视频、边缘部署和主动学习闭环。

## 刻意不做

- 不自研通用标注器，不制作自由拖拽工作流。
- 不提前使用 Kafka、ClickHouse、Kubernetes、多区域或通用规则引擎解决尚未出现的规模问题。
- 不把批量推理、市场计费和供应方内部服务密钥混为同一授权路径。
- 不把“基础设施”暴露成普通用户导航；它属于平台运行边界，用户看到的是项目、购买和供应三类工作。
